通过 github ci 集成到 github pages

静态网页生成好了，接下来就是发布到托管的地方，我选择这种方式：

  1. github private仓库存放markdown原始文档；
  2. private 的 ci 编译完成后，发布产物放到github pages仓库的展示分支中

这样有以下好处：

  1. 源代码和产物分开；
  2. 无需github pro；
  3. 后面如果需要发布到其他托管，新增一个 ci 就可以

简单看了下，原理其实很简单：

  1. github pages通过配置来设置仓库的某个分支某个文件夹是静态网页的放置目录；
  2. 使用zola build来生成public文件夹
  3. 把public文件夹里面的内容放到1. 所设置的分支的文件夹中即可；

我们可以利用github的ci action来完成这个三个动作，而且，已经有开源的docker image帮我们封装好这一切了，ref：操作手册

但是，我们现在的需求其实和上面讲述的不一样，我们release的仓库和ci action所在位置不一样，需要配置一下仓库位置和另一个仓库的权限token，我们这里release后的仓库位置是hizolaw/hizolaw.github.io，而权限token的获得，直接用finedgrained TOKEN即可。

以下是最终的ci脚本：

name: Deploy to GitHub Pages

on:
  workflow_dispatch:
  push:
    branches: [ main ]
  pull_request:
    branches: [ main ]

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - name: checkout
        uses: actions/checkout@v4
      - name: build_and_deploy
        uses: shalzz/zola-deploy-action@master
        env:
          # Target branch
          PAGES_BRANCH: gh-pages
          # Provide personal access token
          TOKEN: ${{ secrets.GH_PAGES_TOKEN}}
          REPOSITORY: hizolaw/hizolaw.github.io
